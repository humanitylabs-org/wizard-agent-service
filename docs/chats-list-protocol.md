# Compact Chats list protocol (opt-in v1)

Old clients continue to receive the original list and detail payloads. New clients request:

- `GET /wizard/hermes/api/sessions?view=list&limit=100&offset=0`: normalized list fields, `list_version: 1`, per-row `listVersion: 1`. One cleaned preview of at most 140 UTF-16 code units; full title; exact lifecycle, grouping, unread inputs, run/idempotency identity, model/provider/lock version and helper-continuation metadata. No raw request/message objects or title history. Empty error/critical/helper/attention fields are omitted. `agent` is only the ID.
- Add `window=archive-50`: every non-Archive row plus the newest 50 **actual** Archive candidates, using the shell's effective lifecycle priority, seven-day aging and card ordering. Shared dispositions and bounded client `overrides` (ID → archived/deferred/restoredAt) participate before selection. The main runtime projects canonical rows in batches of 100, below existing truth-reader caps. Other runtimes are reached only through their existing authorized agent route.
- `archive_total` is the exact candidate count; `archive_returned` is the initial window's Archive count. `archive_cursor` can be sent as `cursor` with the same window/query/overrides/scope to fetch another 50 archived rows. This is an in-memory snapshot cursor, not a durable history identifier.
- Offset pages share `snapshot`. Window snapshots bind account/agent scope, window, query and overrides, expire after 30 seconds, and return 409 on expiry or mismatch. Clients restart once from page 1; they never mark a partial walk complete. The shell preserves early page-1 paint and re-reads the whole selected window every three minutes, catching unchanged-time renames, deletion, archive/restore and changes outside page 1.
- Add `q=<query>` with `view=list` to search outside the retained window. Search returns `search_total` and bounded `searchSnippet`. It checks full title/request/preview, plus visible history in the main runtime's read-only store. Routed agents search their own visible history over the already-authorized HTTP route (four concurrent readers, abortable on disconnect). Internal/tool messages do not qualify. Queries are at most 300 characters. No agent folder discovery or cross-runtime database reads are introduced. When a portable runtime has no canonical reader, the client retains the legacy full-list path and body-search compatibility rather than claiming a truncated window is complete.
- `GET /wizard/hermes/api/sessions/:id?view=detail` returns full `wizard_retry_input` and title history. Missing DB truth falls back to paginated original messages, **not** legacy list-message enrichment (which itself clips text at 1,000). The default detail endpoint is unchanged. New shells fall back to visible message history when an old service does not support this option. Retry always rehydrates and fails closed on read failure; neither 140-character previews nor clipped device snapshots are retry input.

The server does not change authentication, `resolveProxyAgent`, Private admission or thread/run scoping. The shell names the originating agent on every detail/history/search request. Only main-agent list rows enter device snapshots; hydrated request/title-history text is not persisted for compact rows. Search results and off-window details stay in bounded memory, separate from the retained list. Available agent search results publish independently; an unavailable agent produces an explicit partial-search state instead of discarding main-agent hits. Both shells share query cancellation and navigation guards (desktop side-list hosts may return fresh wrapper objects; identity checks must use their ID/agent/navigation state).

## Focused acceptance

- `node --test tests/session-list-*.mjs`: DTO fields, 50-row selection, dispositions/overrides, snapshot expiry/scope/cursor, HTTP legacy/detail/search/auth, routed-agent isolation and secret filtering.
- Focused Vitest: `tests/agents.test.ts tests/agents-sealed-apps.test.ts tests/proxy-queue.test.ts tests/hermes-compat-proxy.test.ts`.
- Paired UX: `qa-chats-slim-list.cjs`, plus existing first-paint, snapshot, session-poll and unified-Chats tests. Browser QA must use synthetic fixtures on the designated remote QA host; never proxy a live Private runtime.

Revision/delta refresh is intentionally deferred. Deployment is paired: publish this service before enabling the new shell; preserve the deployment lane's Private-boundary integration and rollback checks.
